# Project Governance

## Overview

This repository is governed using a maintainer-led model focused on architectural integrity, security, and production realism.

## Decision Making

- Architectural decisions are made by maintainers
- Significant changes require documented rationale
- Security and compliance considerations override convenience

## Change Management

- Backward compatibility is preferred where feasible
- Breaking changes must be documented clearly
- Major architectural shifts require review and approval

## Transparency

All decisions and discussions should be documented via issues or pull requests.
