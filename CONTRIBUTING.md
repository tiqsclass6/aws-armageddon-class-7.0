# Contributing Guidelines

Thank you for your interest in contributing to the AWS Armageddon Terraform Portfolio.

## Contribution Principles

This repository prioritizes:

- Production-grade Terraform practices
- Security-first and compliance-aware design
- Clear documentation and evidence-based validation
- Minimalism and clarity over complexity

## How to Contribute

1. Fork the repository
2. Create a feature or fix branch
3. Ensure Terraform formatting and validation passes
4. Include screenshots or CLI proof where applicable
5. Submit a pull request with a clear description

## Pull Request Standards

- Terraform must pass `terraform fmt`, `validate`, and `plan`
- Changes must not weaken security or compliance posture
- Documentation must be updated where behavior changes

## Out of Scope

- Experimental or non-production patterns
- Hardcoded credentials or insecure shortcuts
- Unverified architectural changes

All contributions are reviewed with an enterprise security and reliability lens.
